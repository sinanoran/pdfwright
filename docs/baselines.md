# Baselines

Numbers measured on 21 November 2026, on the maintainer's Windows machine, `Release`, one run each. They
are **baselines to beat, not benchmarks**: the point is the order of magnitude, and the method.

## The scenario

A table of 1,000 rows and 6 columns (`Row {r} cell {c} text`), A4 portrait, a repeated header row, about
20 pages. The data is generated by `Scenarios/TableData.cs` in the benchmark project, and the Playwright
script (`Baselines/pw.cjs`) builds the same table as HTML.

## Results

| Engine | Time | Memory | Output | Reproducible here? |
|---|---|---|---|---|
| Playwright (Chromium headless shell 1255), `page.pdf` with header and footer | **2,048 ms** total (launch 442, content 901, pdf 705) | **495 MB**, the highest sampled working set of the process tree | 154 KB | yes, below |
| Playwright, 300 rows | 1,164 ms | 382 MB | 70 KB | yes |
| SkiaSharp 4.157 PDF backend, text drawn with `SKCanvas.DrawText` | 279 ms (cold process) | 31 MB peak, 7 MB over the process baseline | 590 KB (the font was barely subset) | **no: a throwaway spike that is not in this repository** |
| Pdfwright | not written yet | | | |

The browser is 288 MB on disk (headless shell) or 453 MB (full Chromium).

## What the Skia spike showed about text (why Pdfwright writes its own writer)

Read back with PdfPig 0.1.16: Latin, Turkish and Thai extract correctly; **Arabic comes back as presentation
forms in visual order and Hebrew reversed**, with no `/ActualText`. Feeding Skia the text and the HarfBuzz
clusters does not change it, and the stock shaper does no bidirectional itemization. SkiaSharp exposes no
structure tree, language or outlines. See section 2 of [`plan-0.1.md`](plan-0.1.md). The spike is not kept
here; this paragraph and the table row are the record, and the Pdfwright corpus plus its read-back test
(from slice S1) are what will keep the claim checked.

## How to repeat the Playwright measurement

The two tools measure different things, so use both:

```bash
cd benchmarks/Pdfwright.Benchmarks/Baselines
npm install playwright-core
# a Playwright "chromium_headless_shell" build (npx playwright install chromium-headless-shell)
export PW_CHROME=/path/to/chrome-headless-shell      # without it, pw.cjs launches full Chromium, not the shell above

# Memory (Windows): the highest working set sampled over the whole process tree, browser included
pwsh sample.ps1 pw.cjs 1000

# Wall time of a fresh process (any OS), median of 10: includes the script's 1.5 s pause before it closes the browser,
# so it is not the 2,048 ms of the table; and its peak working set is that of `node` alone, not of the browser
dotnet run -c Release --project ../ -- cold --runs 10 -- node pw.cjs 1000
```

The `cold` verb is for Pdfwright itself, once it exists: one process, no children, so its figures are complete.
`pw.cjs` prints its own breakdown (launch, content, pdf) as JSON, which is where the table's 442, 901 and 705 ms
come from.
